# oil-writer

Работаешь в корне репозитория `gtoil_content`. Перед написанием прочитай рядом лежащие файлы:
- `style.md` — голос, структура, правила фактов (обязательно)
- `rubrics.md` — 5 слотов дня
- `frontmatter.md` — схема метаданных

## Пайплайн дня

1. **Сырьё.** Прочитай `inbox/news/*.json` за последние 2 дня (их собирает GitHub Actions; формат: список `{title, url, source, published, summary}`). Если файлов нет или релевантных новостей < 2 — добери через WebSearch (новости смазочных материалов, рынок базовых масел, новые спецификации API/ACEA/ILSAC, допуски автопроизводителей, слияния, запуски продуктов). Для каждой новостной статьи открой первоисточник (WebFetch), не пиши по одному заголовку.
2. **Идеи у конкурентов.** Прочитай `inbox/competitors/*.json` (свежие статьи конкурентов, собирает Actions) и `config/competitors.yaml` (у брендов с полем `articles` есть разделы статей; если inbox пуст — ищи их темы через WebSearch с `allowed_domains` = домены из этого файла). Это источник тем и пробелов, а не текста: пиши своими словами, глубже и практичнее, конкурентов в статьях не называй. Ссылки на статьи-идеи клади в `inspired_by` (не в `sources`).
3. **Темы.** Прочитай `content/index.json` (все прошлые статьи) и `config/topics_backlog.md`. Подбери 5 тем по `rubrics.md`. Проверь на повтор: `python3 scripts/dedup.py "<заголовок>"` — при exit-коде 1 бери другую тему. Вечнозелёную тему из backlog после использования отметь там `[x]`.
4. **Написание.** Пиши по `style.md`. Каждая статья — отдельный файл.
5. **Самопроверка** каждой статьи:
   - front-matter валиден по `frontmatter.md`, `status: draft`;
   - у новостей ≥1 URL в `sources`, все цифры и даты из источника;
   - нет выдуманных допусков, номеров спецификаций, цен, цитат;
   - длина тела 3000–6000 знаков (новость можно 1500–3000);
   - `summary` ≤ 280 знаков, годится как анонс в соцсети.
6. **Сохранение.** `drafts/YYYY-MM-DD/NN-slug.md` (NN = 01..05, slug латиницей через дефис). Затем `python3 scripts/index_add.py drafts/YYYY-MM-DD/*.md` — добавит записи в `content/index.json`.
7. **Отчёт.** Таблица: №, рубрика, заголовок, файл, источники. Отдельно — что человеку стоит перепроверить.

## Облачный режим (scheduled task)
Если запуск в облачной сессии и в промпте сказано «открой PR»:
1. Ветка: та, что назначена сессией, иначе `drafts/YYYY-MM-DD` от свежего `main`.
2. Закоммить `drafts/`, `content/index.json`, `config/topics_backlog.md`; push.
3. Открой PR в `main` с заголовком «Статьи YYYY-MM-DD»: таблица статей и список мест `<!-- CHECK -->` для человека.
Merge PR = одобрение всех оставшихся в нём черновиков (Actions `promote.yml` перенесёт их на сайт). Неудачные статьи человек удаляет из PR до мержа.

Вне этого режима не коммить и не публикуй сам: черновики проверяет человек.
